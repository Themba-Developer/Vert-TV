# Native adblock-rust integration and installation

The APK uses Brave's published `adblock` Rust crate **0.13.3**, pinned by Cargo.lock, with a small MPL-2.0 JNI bridge. The Rust engine disables the default single-thread feature so WebView's background request callbacks can safely share it behind a mutex. It matches network rules, resource types, third-party rules and exceptions. Per-page and generic CSS selectors are applied in the top-level WebView. Scriptlet resources, procedural cosmetic actions, redirect replacement resources, browser extension APIs and WebSocket interception are not implemented; this is not the complete Brave browser or a guarantee of ad-free playback. A player may retain an ad timeout even when the ad request is blocked.

Official EasyList and EasyPrivacy snapshots are bundled, with their original headers, source URLs and SHA-256 hashes in `assets/adblock/manifest.json`. The app initializes from bundled/private cached lists off the UI thread, checks for updates at most once daily, and offers manual updates in App settings. HTTPS downloads use fixed official URLs, bounded sizes and format checks. Failed updates keep existing protection. Cosmetic filtering never executes downloaded scripts. The full engine licence and dependency notices are included in the APK.

Filtering is enabled in content WebViews and service-worker requests. PayfastActivity and in-app checkout enter a payment scope which bypasses filtering, including service-worker filtering, until checkout returns/closes. This prevents ad/privacy lists from interfering with payment flows. New content popup windows are refused. If the native library cannot load, the prior small domain blocker is retained and settings explicitly report Basic blocking rather than claiming the Rust engine is active.

## Real catalogue instead of V fallback tiles

MainActivity now opens LibraryActivity after activation. This is a native filtered WebView that loads the shared Vert TV web dashboard at `/app?native=1`. It transfers the existing server session into a Secure/HttpOnly origin-scoped cookie, without exposing a JavaScript bridge. The native layout hides the illustrative hero and starts with the real Dulo popular-movies catalogue; the old Leanback collection grid and its V placeholder artwork are not used as the default dashboard. Web Settings includes an App settings link intercepted only for the exact first-party HTTPS path `/native/settings`. Login/logout cookies synchronize with the native token store when the activity pauses. MainActivity still provides the TV launcher and native initial authentication.

## Build and CPU coverage

Rust 1.99.1, cargo-ndk 4.1.2 and NDK 28.2.13676358 build a single APK containing armeabi-v7a, arm64-v8a, x86 and x86_64 libraries, targeting Android API 26+. Native libraries and APK packaging use 16KB alignment. `preBuild` invokes `scripts/build-native.sh` and generates dependency notices. Install Rust/cargo-ndk and the NDK in Android Studio for local builds. The GitHub workflow tests the real Rust engine, builds all ABIs, checks APK packaging and runs a JNI/filtering/payment-bypass test on an Android 35 x86_64 emulator. Emulator success does not certify every physical TV, codec, WebView version or manufacturer policy.

The welcome download now points to `/install` (short alias `/tv`). `/downloads/vert-tv.apk` is the canonical APK download; the previous debug URL is retained for compatibility. APK responses use the Android package MIME type and attachment filename. Android 8+, a working Android System WebView, sufficient storage and permission to install from the browser/file manager are required. Samsung Tizen/LG webOS cannot run an Android APK. The manifest includes both launchers, a TV banner, optional Leanback and no touchscreen requirement. Installation cannot silently pin itself or bypass a managed TV's policies.

## Release signing

The owner explicitly approved creation of a persistent release key and storage of its credentials in this repository's GitHub Actions secrets. CI uses VERT_ANDROID_KEYSTORE_BASE64, VERT_ANDROID_STORE_PASSWORD, VERT_ANDROID_KEY_PASSWORD and VERT_ANDROID_KEY_ALIAS. The private backup is stored only in the ignored, permission-restricted `.signing/` folder; keep that folder backed up securely. Private keys and credentials must not be committed or printed. The Gradle release task requires signing and never silently publishes an unsigned APK.

The first signed release uses a different certificate from the earlier ephemeral debug/test builds. Android may require uninstalling that older test copy before installing the signed release. Server-side accounts, activation and saved library records remain intact. Subsequent releases must reuse this key and increase versionCode to support in-place updates. CI skips release publication when approved signing credentials are absent; debug artifacts are for tests.
